# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 72-74) | Returns HTTP 200 `{"status": "ok"}` unconditionally without testing MongoDB database connectivity. | If MongoDB is down, unreachable, or failing to accept queries, `/health` still returns 200 OK instead of HTTP 503. | Added a MongoDB ping probe via `client.admin.command("ping")`; catches connectivity exceptions and returns HTTP 503. |
| 2 | `compute_late_minutes` (lines 33-37) | (a) Checks `minutes > 10` where `minutes = int(total_seconds / 60)`, causing 09:40:01 to evaluate to `10 > 10` (False). (b) Uses naive datetime subtraction without converting to IST. (c) Fails on overnight shifts crossing midnight. (d) Does not truncate instant to whole seconds before calculation (R1). | A punch-in at 09:40:01 for a 09:30 shift gives 601 seconds, returning 0 late minutes instead of 10 (violates R2). An overnight shift punch-in before shift end evaluates against the wrong day. | Truncated instant to whole seconds, converted to IST, determined the proper shift start datetime in IST (accounting for overnight shift date offset), evaluated `elapsed_seconds > 600`, and returned `elapsed_seconds // 60`. |
| 3 | `compute_work_hours` (lines 40-41) | Uses Python's built-in `round()`, which applies banker's rounding (round half to even) and IEEE-754 floating-point inaccuracies instead of half-up rounding (R4). Fails to truncate instant to whole seconds. | Values like 2.555 hours round down to 2.55 instead of 2.56. Sub-second timestamps alter work hour totals. | Truncated instants to whole seconds, calculated duration using `Decimal(seconds) / Decimal(3600)`, and applied `quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)`. |
| 4 | `compute_overtime` (lines 44-47) | (a) Missing the 30-minute minimum qualification threshold (R3). (b) Does not increment shift end to the following calendar day for overnight shifts (`shift_end <= shift_start`). | 25 minutes past shift end returns 25 instead of 0. For an overnight shift (22:00-06:00), punch-out at 06:40 next morning checks against day 1 shift end, producing >1400 minutes of overtime instead of 40. | Handled overnight shifts by setting shift end to the next calendar day (`date + 1 day`), computed floor minutes, and returned `minutes` only when `>= 30`, otherwise 0. |
| 5 | `create_employee` (lines 78-86) | Uses `find_one` followed by `insert_one` (check-then-insert) without a database unique index, leaving the endpoint susceptible to concurrency race conditions. | Concurrent `POST /employees` requests with identical `emp_code` both pass the check and insert duplicate documents. | Created a unique index on `employees.emp_code` at startup and caught `pymongo.errors.DuplicateKeyError` to return HTTP 409 Conflict. |
| 6 | `create_employee` & `EmployeeIn` (lines 53-61, 82-85) | (a) Does not validate that `shift_start != shift_end`. (b) Lacks regex pattern validation for `emp_code` (`^EMP\d{4,6}$`), `email`, shift times (`HH:MM`), and `joined_on`. (c) Uses local naive `datetime.now()` for `created_at` and serializes it as an ISO string instead of epoch milliseconds integer. | Creating an employee with `shift_start == shift_end` succeeds instead of returning 422. `created_at` in JSON response is a string rather than an integer count of milliseconds. | Added Pydantic field validators and model validators enforcing all schema constraints; stored UTC datetime in MongoDB and serialized `created_at` as epoch milliseconds integer. |
| 7 | `list_employees` (line 93) | Buggy pagination offset formula: `skip = page * page_size`. | Requesting `GET /employees?page=1` skips the first 20 records and returns items 21-40. | Corrected the pagination offset formula to `skip = (page - 1) * page_size`. |
| 8 | `list_employees` (lines 94-95) | (a) `total = db.employees.count_documents({})` counts the entire collection ignoring the `department` query filter (violates R10). (b) Missing required sorting by `emp_code` ascending. | Filtered employee queries return incorrect `total` count. Response records are returned in undefined order. | Replaced with `db.employees.count_documents(q)` and appended `.sort("emp_code", 1)` to the cursor. |
| 9 | `punch_in` (lines 100-104) | If an unknown `emp_code` is provided, `emp` is `None`; accessing `emp["shift_start"]` raises an unhandled `TypeError` (HTTP 500). | `POST /attendance/punch-in` with non-existent `emp_code` crashes with 500 Internal Server Error instead of 404 Not Found. | Added employee existence check; raised `HTTPException(404, "Employee not found")`. |
| 10 | `punch_in` (lines 102-103) | (a) Derives attendance date from server's local time rather than IST calendar date. (b) Does not handle overnight shifts where punch-in before `shift_end` belongs to the shift starting on the previous calendar day (R1). (c) Accepts timestamps in seconds (< 100000000000). | Punch-in at 01:00 IST for a 22:00-06:00 shift assigns today's date instead of previous day's shift date. Out-of-range epoch seconds return 201 instead of 422. | Converted instant to IST, applied overnight shift date deduction when `time < shift_end`, and enforced epoch milliseconds range validation. |
| 11 | `punch_in` (lines 104, 118-121) | (a) Relies on check-then-insert without a unique index on `(emp_code, date)`, permitting duplicate records under concurrency. (b) Leaks internal MongoDB ID as `"id": str(res.inserted_id)`, violating the API contract. | Concurrent punch-ins for the same date both succeed. Response body contains `"id"` field not in the OpenAPI schema. | Created a unique compound index on `(emp_code, date)`, handled `DuplicateKeyError` to return HTTP 409, and removed `id` / `_id` from the response. |
| 12 | `list_attendance` (lines 144-147) | Reads the entire filtered dataset into Python memory (`list(db.attendance_logs.find(q))`) and sorts in Python. Also sorts only by `date` descending, omitting secondary sort. | High memory consumption and request timeouts on ~100k records. Missing secondary sort by `emp_code` ascending. | Handled sorting and pagination directly inside MongoDB using `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)` backed by compound indexes. |
| 13 | `list_attendance` (lines 125-150) | (a) Missing validation for `date_from > date_to` (must return 422). (b) Returns `"id"` field. (c) Returns raw BSON datetimes rather than epoch milliseconds. (d) Crashes or omits defaults on legacy seeded documents missing `half_day` or `history`. | `date_from > date_to` returns 200 instead of 422. Datetime fields are serialized as strings or ISO. Legacy records fail validation. | Validated date query parameters; normalized missing `half_day` (False) and `history` ([]); serialized all datetime instants to epoch milliseconds integer. |

### Examined and Decided Not a Defect:
- **Plain text `regularized_by` / `reason` without authentication:** The assignment and problem statement explicitly note "free text, no authentication in this assignment". Retaining plain string inputs for author and reason conforms directly to the contract.
- **PyMongo returning UTC datetimes:** PyMongo's BSON date representation maps natively to UTC Python datetimes. Converting datetimes at the boundary (to IST for shift boundary comparisons and to epoch milliseconds integers for JSON responses) is idiomatic and matches the architecture requirements.
